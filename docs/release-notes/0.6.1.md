# Sessions 0.6.1 Alpha

Install Sessions with a branded setup, open it straight away, and see an app icon that
matches the Sessions logo.

Sessions is in Alpha: its core workflow is available for everyday testing, while
features and saved-data formats may change. Feedback and bug reports are welcome.

## Changes

- **A branded installer.** Setup shows Sessions artwork and walks through Welcome, Ready
  to install and Finished. It still installs for your Windows user in a fixed folder,
  keeps your saved Sessions and preferences, and asks you to close Sessions first if it
  is running. There are no folder or license-acceptance steps.
- **Launch Sessions after installing.** The Finished page offers **Launch Sessions**,
  ticked by default. It opens Sessions as your Windows user. Silent installs, repairs and
  removals never launch it.
- **An app icon that matches the Sessions logo.** The window, taskbar, Start menu and
  Installed apps icon now shows the logo's overlapping cascade of squares, with the two
  back squares translucent, instead of three separate solid squares.
- **Fuller Installed apps details.** Windows lists a support link (issues), an update
  link (releases) and a short description beside the existing project link and icon.
- Running Setup again for the installed version offers the standard Repair and Remove
  choices.

## Compatibility

No library or preferences format change: 0.6.1 reads and writes library v6, like 0.6.0.
Upgrading from 0.6.0 or an earlier release works as before; see the
[0.6.0 notes](0.6.0.md#compatibility) if you are coming from 0.5.0 or earlier.

## Validation and Alpha limits

Local installer validation passes clean solution/MSI builds with WiX validation,
self-contained Windows x64 publishing and dependency-notice collection, plus 150 Core
and 266 App tests (31 opt-in native skips). Inspection of the built MSI confirms the
Welcome, Ready to install, progress and Finished dialogs with the branded bitmaps and
no license dialog, the Launch Sessions action conditioned on a new install or upgrade,
the unchanged close-Sessions-first check, and the new Installed apps properties.

In Windows Sandbox, a fresh interactive install showed the branded pages, and Launch
Sessions (ticked by default) opened the installed app. Running Setup again offered Repair
and Remove; removing while Sessions was running was refused with the close-Sessions
message and kept the installation, and removal after closing Sessions finished without
the launch option. A silent upgrade from the published 0.6.0 installed 0.6.1. Unticking
Launch Sessions, an interactive upgrade and Repair were not exercised.

Installer dialogs are drawn by Windows Installer and do not follow dark mode. Real-app,
native accessibility, ordinary nonadministrator installation and installed UAC limits
from earlier releases still apply. MSI and app binaries are unsigned, so Windows Smart
App Control, when turned on, may block the installer. In Windows Sandbox, where Smart
App Control starts in evaluation mode without Defender, Windows waits about two minutes
before Setup appears and again after Install; turn Smart App Control off inside the
Sandbox to avoid this.

## Upgrading

Close Sessions and run `Sessions-0.6.1-win-x64.msi`. The per-user Windows x64 installer
includes .NET and preserves saved Sessions, appearance and plugin preferences.
There is no automatic updater.

## Source and checksums

`Sessions-0.6.1-source.zip` contains matching GPL-3.0-only Sessions source and build
scripts. Dependency notices are installed in `licenses` and can be read from
Settings → About Sessions → Licenses and notices. `WiX-7.0.0-source.zip` supplies the
matching MS-RL source for the installer's embedded WiX utility actions and standard
dialogs. `SHA256SUMS.txt` covers the MSI and both source ZIPs.
